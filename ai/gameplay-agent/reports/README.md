# Report output

Run reports are created in a new `reports/<UTC run-id>/` directory and are retained locally without automatic cleanup. `report.json` is the machine-readable source of truth; `summary.md` is the concise human view; `defects.json` contains stable IDs, category, severity, reproduction steps, screenshots, authoritative state, and a three-cycle repair limit. Each scenario has a `result.json`, EXE log, authoritative state snapshot, and screenshots captured from the Chromium renderer. `result.json` separately records whether Electron confirmed a visible window and that input was synthetic CDP input. Blocked input and popup-dismissal failures include before/after popup DOM, Canvas, clipped hit-test state and the bounded operation log. `ESCALATED-<run-id>.json` records defects that exhausted their three repair cycles.

Run `npm run gameplay-agent:report` to locate and summarize the latest completed run. Missing GUI or EXE is `NOT_VERIFIED`, never `PASS`.

V5.9-I.1 campaign scenes additionally retain `evidence/home-arena-input.jsonl` with actual hit-tested inputs and authoritative before/after projections, and `evidence/home-arena-metrics.json` with wall-clock stage timings, actual rewards, restart comparisons, and per-minute retained-resource samples. Milestones include first second, first kill, critical, stage transitions, storm, elite, first/fifth minute and restart. Failed runs retain partial metrics; only a completed twenty-minute soak can satisfy stability acceptance.
