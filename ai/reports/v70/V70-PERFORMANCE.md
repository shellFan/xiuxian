# V7.0 性能报告（TASK-074/083）

数据来源：打包 EXE CDP `Performance.getMetrics` 采样（30 秒间隔）+ tasklist 进程内存。
完整逐样本数据：`v70-exe-soak.json`（60 分钟 × 120 采样）。

## 1. 采样指标（EXE，后台运行）

| 指标 | 观察区间（多轮采样） | 评估 |
|---|---|---|
| JSHeapUsedSize | 25~36 MB 波动，无单调增长 | 无 JS 内存泄漏证据 |
| DOM 节点 | 首页 ~450 / 卡牌战斗 ~160，按页面稳定 | 常驻舞台改造后无每秒节点膨胀 |
| 异常 | exceptions=0（全程） | 渲染层零未捕获异常 |
| HTTP 4xx | 0（全程） | 资源全部命中 |
| sprite 2xx | 35~37 后稳定（缓存生效，无重复请求风暴） | V6.8 P0-04 修复保持 |
| 渲染进程崩溃 | 0 | 无 oom/crash |

对照 V6.8 同口径：JS heap 25.5MB 波动、DOM 427~434、0 异常——本轮在功能大幅
增加（战斗舞台常驻、卡牌自驱动）下内存与 DOM 规模持平。

## 2. 本轮性能相关改造

1. **战斗舞台常驻**：refresh() 每秒全量重建 → 签名对比 + 节点保留，
   hp/冷却/DPS 局部更新。消除了每秒 ~450 节点的 GC 压力与 sprite 动画重置。
2. **backgroundThrottling:false**：窗口被遮挡时挂机游戏不再冻结（该问题
   在首轮 EXE soak 中实际发生并修复——战斗停在第 5 关 5 分钟）。
3. **Toast 位置调整**：纯 CSS，无性能影响。

## 3. 已知限制

- 采样在 CDP 附着的同一渲染进程内进行，`Performance.getMetrics` 的
  JSHeap 值不含原生/GPU 内存；进程级内存由 tasklist 快照辅助记录。
- FPS 未接入自动化采样（引擎内部 rAF 无对外计数器）；以「动画连续性」
  的截图/探针证据替代（sprite 帧推进 + 常驻舞台）。

## 4. 低性能模式（TASK-059）

现有能力：音效并发由服务层管理；渲染层已消除每秒整页重建（本轮）。
未实现独立的低画质开关（粒子/震屏/飘字上限已有代码级常量），
标记 NOT_VERIFIED（无自动化手段验证视觉降级效果）。
