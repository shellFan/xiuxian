# IAA Design — 自愿激励

设计原则：不看广告可以正常玩；只提供加速、翻倍、重试或额外奖励。V1以Rewarded Video为主，无强制插屏、无伪装普通按钮、无关不掉的倒计时、无失败就弹广告。当前Provider接口不等于这些位都已接通微信广告，所有新增位须Platform/Reward Owner实现并验收。

| 位 / ID | 出现位置与触发 | 频率 / 建议每日上限 | 玩家价值 | 失败fallback / 能力 |
|---|---|---|---|---|
| Offline Double / OFFLINE_DOUBLE | 未结算离线预览的次按钮“看广告 ×2” | 每个有效settlement一次；最多3次/日；零收益不展示 | 领取该次2倍总收益 | 失败可普通领取1倍；已结算不再展示；当前claimDouble与claimNormal互斥 |
| Mind Recovery / MIND_RECOVERY | 道心帮助面板次按钮，低道心且玩家主动打开 | 两次至少10分钟；3次/日 | 候选恢复20道心，预览实际不超上限的量 | 不恢复；继续摸鱼恢复；需确认placement处理与持久限额 |
| Promotion Retry / PROMOTION_RETRY | 晋升失败结果页 | 每次失败事务最多1次；3次/日 | 一次重试机会，非必定成功 | 保留失败结果，返回修炼；不重扣未经说明的成本 |
| Event Reroll / EVENT_REROLL | 未处理事件的“换个事件”次入口，经确认 | 每事件一次，间隔10分钟；2次/日 | 换事件而非保证好事件 | 保留原pending；需原子替换/去重能力，未实现则隐藏 |
| Work Boost / WORK_BOOST | 工作详情中的可选奖励卡 | 不叠加，生效期间禁用；3次/日 | 候选工作收益+20%，5分钟，明确仅工作产出 | 不加buff，普通工作照常；由Buff/Work Owner确认范围 |
| Instant Recruit / INSTANT_RECRUIT | 招募详情面板，棋盘有空位时 | 5分钟间隔；3次/日 | 候选免费招募1个基础牛马 | 不扣工资，不放入满盘；先验证空位及结果幂等，失败提示重试 |
| Auto Merge / AUTO_MERGE | 合成说明页独立奖励项 | 无可合成对时不展示；2次/日 | 候选执行1次确定性安全批量合成，非永久托管 | 保留原棋盘；需要批处理原子能力，本轮不实现 |

上限是**产品建议**，未写入任何服务；未完成持久限额、跨日规则和真实Provider验收前，不启用候选位。界面remaining只读服务值，不通过隐藏按钮冒充限额执行。

## 明确文案

- 默认主按钮永远是正常玩法：“收下”“继续修炼”“返回工位”。
- 奖励次按钮：“看广告 ×2”“看广告 恢复20道心”“看广告 再试一次”。动态奖励变更后显示真实量，不能标20实得5而不说明。
- 请求前说明“完整观看后获得奖励”；无填充：“暂时没有广告，可继续正常游玩”；中途关闭：“本次未获得广告奖励”；结果未知：“奖励确认中，请稍后查看”，不能让玩家重刷同一事务。
- 不得预选同意、自动开始或将广告点击当教程目标。

## 生命周期与恢复

AVAILABLE → REQUESTING → SHOWING → VERIFYING → GRANTED；失败细分UNAVAILABLE/CANCELLED/FAILED/UNKNOWN。只有Provider确认且业务提交成功才GRANTED。发奖绑定placement+entityId+requestId持久去重，页面销毁后结果仍交服务处理。普通按钮不被广告失败永久锁住。

Offline当前接口是未结算时一次性选1倍或2倍，不能按“先领1倍再加1倍”实现UI；若产品以后选追加式，必须主线改事务协议。本包采用现有互斥语义。

审核清单：无广告路径完整；拒绝/关闭/无填充/网络失败/后台恢复/重复回调/跨日/重启后限额/满盘变化都可恢复；数据与次数不由UI计算；收益上限经主线模拟批准。广告平台具体政策与最新API需正式接入时查官方文档，本文件不声称平台合规已验收。
