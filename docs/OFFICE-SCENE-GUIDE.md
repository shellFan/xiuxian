# 办公室场景规划

办公室是合成舞台，不做装修经营系统。装饰不可点、不产新收益；工位格数保持当前4×4，背景变化不能改变拖拽几何。

当前office.json只有5档：共享工位(职业1–2)、普通工位(3–4)、隔断工位(5–6)、主管办公室(7–8)、经理办公室(9–10)。7视觉阶段不是7个已实现officeLevel，不能接入成新增升级算法。初始/终局子皮肤选择需主线批准条件，未批准只用对应默认候选。

## 分层与构图

FarWindow（天空与楼群）→ Wall（门/会议室/需求墙）→ DeskBack（屏幕）→ MergeBoard（真实交互）→ DeskFront（低矮边缘，不挡目标）→ Atmosphere（少量尘光）。背景透视向棋盘中心收敛，棋盘始终平面俯视，不能让装饰透视改变格子中心。

750×1334安全内容内，舞台位于HUD与棋盘之间；19.5:9和20:9向上扩展窗/墙而不是拉高桌椅。顶部与底部要有可裁边界，关键人物和法器不得放裁切区。背景画面不烘焙按钮、字、资源数值或格线。

## 轻量资源

墙/窗/静态桌面分atlas，小物件按需加载；同等级共用显示器、椅子、阴影。首版只允许路由器灯、咖啡气、便签摆动三种氛围动效，减少动态全部停。音效不因每个装饰实例叠加。

验收：暗化后HUD仍清晰，主CTA仍最突出；满盘不遮牛角；拖拽路径没有装饰触摸拦截；七张场景缩略能辨成长但同属一个办公室世界；无真实公司logo、个人信息或二维码。
